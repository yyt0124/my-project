02 / Request lifecycle

一筆刊登請求怎麼走

前端不直接連資料庫。每次操作都經過後端權限檢查與業務規則，再寫入資料。

STEP 01

填寫與送出

使用者輸入物品資料；照片以 FormData 上傳，其他欄位以 JSON 傳送。

STEP 02

Security 驗證

Spring Security 讀取登入 Session，後端使用會員身分決定物主權限。

STEP 03

Controller 分派

SharedItemController 接收 REST 請求，檢查路由及參數並呼叫服務層。

STEP 04

Service 套用規則

設定固定取物點、確認借還狀態與物主權限，處理照片及索引更新。

STEP 05

寫入並回應

JPA 儲存到 MySQL，搜尋文件同步到 Elasticsearch，API 回傳 JSON 給前端。

04 / Data & persistence

主資料、搜尋與照片分開保存

不同儲存元件有不同責任。MySQL 是主要資料來源，其他元件不能取代它。

元件保存內容用途與特性
MySQL 8會員帳號、共享物品與借用狀態正式主資料來源；Spring Data JPA / Hibernate 負責讀寫。
Elasticsearch 9共享物品搜尋文件提供全文搜尋；文件可依 MySQL 主資料重新建立。
Docker Volume照片檔、資料庫資料與搜尋索引容器重新建立後仍保存資料；雲端 Volume 位於 EC2 主機。
Redis 7目前無共享主流程資料容器與連線設定存在；目前沒有快取或工作佇列功能接入。

05 / Runtime environments

本機開發與雲端展示

兩個環境沿用相同的 app 與資料服務組合，連線方式和對外入口則依環境設定。

本機｜Docker Compose

compose.yaml · 開發與除錯

  • 應用程式Spring Boot 容器，8080 僅綁定本機回環位址。
  • 資料服務MySQL、Elasticsearch、Redis 由 Compose 啟動。
  • 上傳照片掛載 item-photos Volume 保存。
  • 本機連接埠app 8080、MySQL 主機 3307、Elasticsearch 9200、Redis 6379。

雲端｜AWS EC2

Amazon Linux 2023 · compose.aws.yaml

  • 容器編排EC2 上執行 app、MySQL、Elasticsearch 與 Redis。
  • 公開入口目前展示使用 cloudflared Quick Tunnel，將 HTTPS 轉送至 Compose 網路的 app:8080。
  • 持久化資料MySQL、搜尋索引和照片使用 Docker Volumes。
  • 重新啟動Compose 服務設有 unless-stopped；主機及 Tunnel 仍須運行。

網址提醒：Cloudflare Quick Tunnel 網址是臨時網址，停止或重建 Tunnel 後可能改變。GitHub Pages 這份架構說明是另一個獨立網站，EC2 或 Tunnel 停止時仍可瀏覽。
